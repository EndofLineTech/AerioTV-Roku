# Roku TV parity crosswalk

**Snapshot:** 2026-11-19, Roku development source `18916a0` (manifest 0.3.103), and the local Beads database. This is not the v0.3.102 release matrix. The [September audit](PARITY-AUDIT.md) remains the historical baseline; its row IDs and pinned upstream citations still identify the original behaviors. `AerioTV-Roku-e3e.1` owns this reconciliation; `e3e.25` owns integrated acceptance. Short IDs below have prefix `AerioTV-Roku-` (`bd show AerioTV-Roku-<id> --json`).

**Evidence:** **Native** = a prior result on Roku for the stated path, not necessarily on this exact commit. **Fixture** = automated/model or synthetic input evidence, even if run on Roku; not a provider or physical pass. **Source** = implementation or active routing at this pin without a matching native outcome established here. **Missing** = the specified behavior is not active at this pin. **Disposition** = an explicit scope choice or platform difference, not delivery. Physical results are called out separately where important. This review did not run a device, contact a provider, fetch source, or change Beads. Pending branches and local modifications are not counted as integrated.

## Reference availability

- **Apple October:** The locally staged [`fe7ad4c` tree][oct-tree], including the [October changelog][oct], [setup handoff][oct-setup] and [Sync schema][oct-sync], was available. The cited files match the pinned Git tree. The comparison uses TV call sites and guards, not just release-note labels. The last release in that changelog is **v1.8.44**. The October documents describe the shared design, not proof of both peers shipping at that revision (the October Sync document says draft).
- **Apple September:** Commit `8d5818456e0f4421d93b8ff120ad878d63331091` exists in a partial local Git store. Of the 58 distinct files cited by the old audit, only `GuideJumpSheet.swift`, `ChannelNumberEntry.swift`, `LocalRecordingSession.swift` and `VODCatalogStore.swift` were readable at that pin without fetching. The older observations are attributed to the historical audit; the newer tree is not silently substituted for old blobs.
- **November peer contracts:** The local upstream Roku interop handoff (2026-11-08, Apple 1.8.45 / Android 0.5.14), shared Wire v1 setup handoff and Sync v3 contract checked on 2026-11-11, and local peer encoder sources were available. The November Sync document reports implementation on Apple `d75589d`/Android `44a76a7d` and describes the username-derived key and later row/hold fixes. The Roku [delivery record](MRR-DELIVERY-STATUS.md) pins the tested encoders (Apple `8df372291da4a858b0081e291a7fa5cbe398f9f8`, Android `63d70f00ac6b7e1148093786942468514c618b62`). This supersedes “Apple setup planned” for November, not retroactively for October. Neither the full Android TV source tree at [September `7bf4a2dd`][android-sep] or at the November peer pin, nor upstream TV binaries, were available for this review. Android conclusions here are limited to the supplied shared contracts and the named encoder evidence.

## Confirmed October TV gaps now tracked

These are source-confirmed October TV behaviors, not defects reproduced in a native run. The dedicated beads track the gaps; their creation does not change implementation or acceptance at the audited Roku pin.

Roku's [Player settings](../source/SettingsModel.brs) and [key dispatch](../components/PlayerRemoteInput.brs) lack the equivalent toggle/action; native FF/REW and the existing seek timeline are different controls. `34y.12` delivered timeline/skip/Go Live; `jmet` is verification of the existing interval, not this feature. | `zyry` |
| **Independent Guide and Movies/Series display scales** | tvOS exposes separate [Live TV][oct-guide-scale] and [Movies/Series][oct-vod-scale] scale controls. | **Two-step Back from library/Settings roots** | On [tvOS][oct-tab-back], Back from root content focuses that tab's pill without leaving the page; Back from the pill returns to Live TV. At Roku's library roots, the [close handlers](../components/MediaNavigation.brs) return to Guide; [Settings](../components/SettingsNavigation.brs) first unwinds its own panes and closes to Guide from its root. `e3e.20` remaps Back *in* Guide; `dgt`/`mrr.11` cover current Roku navigation, not this upstream two-step behavior. | `9jr0` |
